# Pass 5 — UX, Input, and Accessibility

*Scrapwright audit 2026-04-16. Findings only.*

## 5.1 Controller + Keyboard + Mouse Parity

### Finding E1 (HIGH — gamepad lockout)

[base_hub.gd:877-916](scripts/base_hub.gd:877): the radial upgrade wheel connects only `mouse_entered`, `mouse_exited`, and `gui_input` on each slot. There is **no `focus_entered` handler**, and no `focus_neighbor_*` wiring between slots. A player using only a gamepad cannot focus-navigate between upgrade cards — the hub upgrade loop is mouse-only.

### Finding E2 (MEDIUM)

[pause_menu.gd:434-464](scripts/pause_menu.gd:434) — buttons style a hover state but not a focus state. Keyboard-navigating the pause menu gives no visible cue which button is selected. Apply `theme_override_styles/focus` or use `add_theme_stylebox_override("focus", ...)`.

### Finding E3 (MEDIUM)

[main_menu.gd:495-506](scripts/main_menu.gd:495) — menu buttons' description label is tied to `mouse_entered` only. Keyboard-only users never see the text. Mirror `focus_entered`.

### Finding E4 (LOW)

[base_hub.gd:90-135](scripts/base_hub.gd:90) — sidebar tab buttons lack `focus_entered` hooks; tooltips are mouse-only.

## 5.2 Input Remapping

### Finding E5 (HIGH)

[keybind_manager.gd:11-17](autoloads/keybind_manager.gd:11) — `REBINDABLE_ACTIONS` covers only: `dodge`, `bark`, `salvage`, `sneak`, `collect`. **Movement (`ui_up`, `ui_down`, `ui_left`, `ui_right`) and `ui_cancel`/pause are not rebindable.** Players who want to move with arrows only (not WASD) or who need accessibility adaptations cannot remap movement. 

### Finding E6 (LOW)

[pause_menu.gd:371-378](scripts/pause_menu.gd:371) — control-reference labels show literal strings "WASD", "SPACE", "F", "SHIFT", "CTRL". After a player rebinds, the labels stay stale. Read current bindings via `InputMap.action_get_events(action)` and format dynamically.

### Finding E7 (LOW)

Gamepad analog stick and deadzone handling verified in `project.godot` (0.2 deadzone for movement; 0.5 for `ui_cancel`). Non-configurable in-game. Acceptable default, but add a deadzone slider in options later.

## 5.3 Wave Transition Input

### Finding E8 (MEDIUM)

[arena.gd:232-250](scripts/arena.gd:232) — the WAVE CLEAR banner + XP vacuum runs during a 1.3s pause-less window. Player input still registers during this window. If the player mashes bite or dodge, the actions are queued but generate no visual response because enemies are gone. Not a crash, but felt as "unresponsive input". Consider calling `get_viewport().set_input_as_handled()` for the banner duration, or setting `player.input_locked = true`.

### Finding E9 (LOW)

Chest phase ([arena.gd:314-346](scripts/arena.gd:314)) sets `get_tree().paused = true` and the chest UI uses `PROCESS_MODE_ALWAYS`. Player remains visible behind the dim panel. Minor polish — a full dim overlay would be cleaner.

## 5.4 HUD Readability

### Finding E10 (MEDIUM)

[hud.gd:51-54](scripts/hud.gd:51) — HP bar is 200×22 px; XP bar same; wave label at `(-222, 8)`. At 960×540 viewport this is fine, but **at 4K fullscreen with stretch "canvas_items"**, text may render with noticeable bilinear blur (see `project.godot:42` `window/stretch/mode="canvas_items"`). Acceptable for pixel-art aesthetic but verify fonts use nearest filter.

### Finding E11 (LOW)

At wave 60+ the HUD top-right wave label and top-left HP/XP bars are mostly unobstructed by enemies (enemies don't crowd corners). Readability is OK. Damage numbers floating off enemies can stack visually — consider "MERGE if same position within 0.1s" for combo hit labels.

- [pause_menu.gd:7-12](scripts/pause_menu.gd:7) — 6 CLR_ constants
- [game_over.gd:7-13](scripts/game_over.gd:7) — 5 CLR_ constants
- [hud.gd:8-14](scripts/hud.gd:8) — HP/XP state colors
- [level_up.gd:8-14,35-44](scripts/level_up.gd:8) — panel + 16 perk colors
- [base_hub.gd:33-58](scripts/base_hub.gd:33) — KEY_COLORS + MAT_COLORS
- [enemy_base.gd:95-135](scripts/enemy_base.gd:95) — 41 TYPE_COLORS
- [destructible_prop.gd:18-41](scripts/destructible_prop.gd:18) — 21 prop colors

### Finding E12 (MEDIUM)

A single ColorPalette autoload or theme resource would centralize these. Today, a palette tweak requires editing 7+ files.

### Finding E13 (LOW)

The 12-color palette claim in `CLAUDE.md` is only a convention — no code enforces it. The TYPE_COLORS table uses 20+ distinct hues.

## 5.6 Color-Blind Accessibility

### Finding E14 (HIGH — dichromatic risk)

[enemy_base.gd:95-135](scripts/enemy_base.gd:95) colors enemies heavily by palette alone:
- Rusher `Color(0.9, 0.2, 0.2)` — pure red
- Spore Walker / Fungal Brute — green
- Frost Sprite / Crystal Bat — light cyan
- Shadow enemies — desaturated purple/gray

Red-green dichromats (~8% of men) will struggle to distinguish Rusher from Spore Walker at a glance. Enemy shape differs (sprite silhouettes), but under wave-60 chaos the **silhouette overlaps are frequent**. Add an outline/tint-intensity option, or give each enemy a distinct shape glyph over its head.

### Finding E15 (MEDIUM)

HP bar transitions green → yellow → red ([hud.gd:8-14](scripts/hud.gd:8)). Deuteranopia collapses this to brown-brown-brown. Consider adding a shape tell: fill reduces from solid → hatched → pulsing.

### Finding E16 (LOW)

Verify enemy_projectile colors. [enemy_projectile.gd](scripts/enemy_projectile.gd) uses stage-tinted projectiles. Rapid glance: no purely red-vs-green dependency.

## 5.7 Pause Behavior

### Finding E17 (MEDIUM — verified correct)

Dynamic timers (`BugSwarmTimer`, `VineSnareTimer`, `PerkRegenTimer`, etc.) all set `process_mode = Node.PROCESS_MODE_INHERIT`. When `get_tree().paused = true`, they correctly halt. ✓

### Finding E18 (LOW)

[audio_manager.gd](autoloads/audio_manager.gd) does not explicitly duck music during chest UI / pause. Current `_music_player` keeps playing. For ambient feel this is arguably fine; mentioning for completeness.

## 5.8 Audio Routing

### Finding E19 (MEDIUM)

[pause_menu.gd:485-486](scripts/pause_menu.gd:485) and [main_menu.gd:371-388](scripts/main_menu.gd:371) — the master volume slider uses `AudioServer.set_bus_volume_db(0, ...)` — **bus index 0**. This works iff the Master bus is index 0 (true by default), but is fragile if anyone reorders buses. Prefer `AudioServer.get_bus_index("Master")` once, or pass the bus name.

### Finding E20 (LOW)

[audio_manager.gd:52](autoloads/audio_manager.gd:52) — Arcane Book SFX reuses `spark_coil.wav`. Likely placeholder — content gap.

## 5.9 Tutorial Coverage

### Finding E21 (MEDIUM)

[tutorial_arena.gd](scripts/tutorial_arena.gd) teaches: movement, dodge, bite, sneak, dig/trap, salvage. **Not taught**: orbital weapons, perks / level-up, chests, keys, materials, cards, the Bark ability as distinct from bite, Collect. A first-time player reaches wave 2 without ever being told what orbitals do.

### Finding E22 (LOW)

Tutorial is skippable but does not show progress / step count. Adding "Step 3 of 6" on screen would frame expectations.

## 5.10 Level-Up Perk Pool

### Finding E23 (MEDIUM — potential depletion)

[level_up.gd:65-74](scripts/level_up.gd:65) `ALL_PERKS` array is static. At wave 70+ with all 6 orbital slots capped at Lv20 and every stat perk picked 4+ times (with diminishing returns), the eligible pool shrinks. The UI code should handle small pools, but the current pool builder doesn't short-circuit if fewer than 3 cards can be offered. Needs a stress test at wave 70+.

### Finding E24 (LOW)

[level_up.gd:189-262](scripts/level_up.gd:189) — panel width scales with card count. If `perk_choices_level` upgrade is purchased, 4 cards show — width pushes ~580px. On a 960px viewport that's 60% coverage but during pause so acceptable.

## 5.11 Game-Over & Victory Flows

### Finding E25 (MEDIUM)

After the final boss (Scrap King, wave 84), [arena.gd:278](scripts/arena.gd:278) calls `change_scene_to_file("res://scenes/base_hub.tscn")`. There is a separate `credits.tscn` but the code path from `_on_all_waves_complete` to credits is **not obvious**. Verify: does the player see credits on victory, or only return to hub? Short inspection of `arena.gd:1219-1221` suggests credits is only triggered when `wave_num == total_waves` in a special branch. Confirm this runs.

### Finding E26 (LOW)

Death screen ([game_over.gd](scripts/game_over.gd)) shows "YOU DIED" + stats. Distinct from credits. Good.

## 5.12 Profile / Save UX

### Finding E27 (MEDIUM)

[main_menu.gd:950-998](scripts/main_menu.gd:950) — profile deletion uses a 3-second confirmation window (click "Delete", then "Confirm within 3s"). If the player navigates away mid-window, state is held in closure and behaves inconsistently. Replace with a **modal confirmation dialog** that blocks other input.

### Finding E28 (LOW)

[main_menu.gd:535-549](scripts/main_menu.gd:535) — "Continue" button visibility logic checks multiple conditions. If all conditions are false, button is hidden with no explanation. A tooltip "No saved run found" on the disabled state would be kinder.

### Finding E29 (LOW)

No "Export save" / "Back up save" functionality. Given the 77-run blueprint grind, a save backup option would protect players from data loss.
